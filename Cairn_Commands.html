⌘ Cairn — Command Cheat Sheet

Run, commit & release Cairn

Copy each block, paste it into the Command Prompt, press Enter. Do the steps in order the first time; after that you'll mostly use steps 4 and 6.

How to open CMD in the right place: Open the JOR_CLAUDE folder in File Explorer → click the address bar → type cmd → press Enter. A black window opens already pointing at the app folder.
1

Clear the stuck git lock (one-time fix)

A leftover lock file is currently blocking git. This removes it. Safe to run — it only deletes a temporary file.

cmd
del /f /q .git\index.lock
2

Tell git who you are (one-time)

Only needed if git ever complains about identity. Skip if commits already work.

cmd
git config user.name "Jai Akash"
git config user.email "jaiakashj121420004@gmail.com"
3

Commit everything done so far

Stages every change and saves a snapshot to your local history.

cmd
git add -A
git commit -m "feat: Wave 4 broker integration + docs and app-overview pages"
If it says nothing to commit, you're already saved — move on.
4

Run the app locally

Installs dependencies (first time only) and launches Cairn in development mode.

cmd · first time
pnpm install
cmd · every time
pnpm --filter desktop dev
If pnpm isn't recognized, install it once with: npm install -g pnpm. If --filter desktop errors, try pnpm dev from inside the apps\desktop folder.
5

Connect to GitHub (one-time)

You don't have a remote yet. First create an empty repo on GitHub (no README), copy its URL, then link it. Replace the URL below with yours.

cmd
REM check current branch name (likely feat/vault-enrollment-server or master)
git branch --show-current

REM link your GitHub repo (paste YOUR url)
git remote add origin https://github.com/YOUR-USERNAME/cairn.git

REM push your main branch and remember it
git push -u origin master
GitHub will ask you to sign in the first time. Easiest path: install GitHub Desktop or the GitHub CLI (gh auth login) to handle the login. If your branch isn't master, swap it in the last line (e.g. git push -u origin main).
6

Push a new version & cut a release

Do this each time you want to publish an update. It bumps the version number, saves it, tags it, and pushes the tag to GitHub.

cmd · save your work
git add -A
git commit -m "describe what changed in this version"
git push
cmd · bump version (pick one) 
REM 0.1.0 -> 0.1.1  (small fix)
pnpm version patch

REM 0.1.0 -> 0.2.0  (new features)
REM pnpm version minor

REM 0.1.0 -> 1.0.0  (big release)
REM pnpm version major
cmd · push the version tag 
git push
git push --tags
Create the GitHub Release: Go to your repo on GitHub → Releases → Draft a new release → choose the tag you just pushed (e.g. v0.1.1) → add notes → Publish release.

Prefer the command line? With GitHub CLI installed:
cmd · release via gh CLI 
gh release create v0.1.1 --title "Cairn v0.1.1" --notes "What changed in this release"
To attach an installer (the .exe users double-click), first build it, then add the file to the release:
build the Windows installer → pnpm --filter desktop build
the installer lands in apps\desktop\release\ — upload it on the Releases page, or:
gh release upload v0.1.1 apps\desktop\release\Cairn-Setup-0.1.1.exe
